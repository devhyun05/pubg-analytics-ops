# 기술 의사결정 기록

이 문서는 프로젝트에서 선택한 기술과 그 이유, 검토한 대안, 선택에 따른
제약을 기록한다. 구현 결과가 바뀌면 기존 결정을 삭제하지 않고 변경 이유와
새 결정을 추가한다.

## ADR-001: 대규모 원본 CSV 조회에 DuckDB 사용

- 상태: 채택
- 적용 단계: 원본 프로파일링, 데이터 품질 검사, 분석 대상 생성
- 관련 데이터: deaths CSV 약 9.2GB, 65,370,475행

### 배경

이 프로젝트의 원본 deaths 데이터는 CSV 5개와 65,370,475행으로 구성되어
있다. 전체 CSV를 한 번에 메모리에 적재하거나 PostgreSQL에 먼저 복제하지
않고도 다음 작업을 반복 실행할 수 있어야 한다.

- 여러 CSV를 하나의 입력처럼 조회
- 필요한 컬럼과 행만 선택
- `GROUP BY`, `JOIN`, 윈도 함수로 프로파일링 및 품질 검사
- 입력 행 수, 제외 행 수, 출력 행 수 대사
- 동일한 기준으로 새 배치 또는 재실행 처리

### 결정

원본·상세 CSV를 읽고 정제하는 실행 엔진으로 DuckDB를 사용한다.
PostgreSQL은 전체 원본 CSV 저장소로 사용하지 않고, 품질 검사 결과,
파이프라인 실행 이력, 최종 집계 테이블을 저장하는 역할로 제한한다.

현재 작성하는 분석 로직은 가능한 한 표준 SQL 문법을 사용한다.
`SELECT`, `WHERE`, `GROUP BY`, `JOIN`, `CASE WHEN`, 윈도 함수 등은
PostgreSQL에서도 이해할 수 있는 형태로 작성하고, CSV를 직접 읽는
`read_csv_auto`와 같은 입력 부분만 DuckDB 기능에 의존한다.

### 선택 이유

1. DuckDB는 CSV를 데이터베이스 테이블에 먼저 적재하지 않고 직접 SQL로
   조회할 수 있다.
2. 필요한 컬럼과 행만 처리할 수 있어 대용량 CSV 전체를 pandas
   DataFrame으로 한 번에 메모리에 올리지 않아도 된다.
3. 여러 파일을 glob 패턴으로 읽을 수 있어 동일한 스키마의 deaths CSV
   5개를 하나의 데이터셋처럼 처리할 수 있다.
4. 분석용 `JOIN`, 집계, 윈도 함수와 같은 SQL 기능을 지원하므로 데이터
   품질 규칙과 지표 로직을 SQL로 명확하게 표현할 수 있다.
5. 별도 데이터베이스 서버 없이 Python 프로세스 안에서 실행할 수 있어
   로컬 프로파일링과 반복 개발의 운영 부담이 작다.
6. 원본 처리와 결과 저장의 책임을 분리할 수 있다. DuckDB는 대규모
   파일 처리에, PostgreSQL은 운영 결과와 BI 조회에 집중한다.

### 검토한 대안

#### pandas로 전체 CSV 적재

채택하지 않았다. 약 9.2GB의 CSV는 파싱 후 메모리 사용량이 원본 파일
크기보다 커질 수 있다. 전체 데이터를 한 번에 DataFrame으로 적재하는
방식은 프로젝트의 대용량 처리 원칙과 맞지 않는다.

단, 작은 결과를 출력하거나 테스트용 샘플을 다룰 때 제한적으로 사용하는
것은 별개의 결정이다.

#### PostgreSQL에 전체 원본 적재

채택하지 않았다. 분석 전에 65,370,475행을 복제하면 적재 시간, 저장 공간,
인덱스 관리와 재실행 시 중복 방지 작업이 추가된다. 또한 이 프로젝트는
원본·상세 이벤트와 운영용 집계 저장소의 역할을 분리한다.

#### MySQL 사용

채택하지 않았다. MySQL도 적재된 테이블의 집계에는 사용할 수 있지만,
현재 구조에서 PostgreSQL과 별도로 도입할 운영상 이점이 없다. 데이터베이스
종류를 추가하면 Docker 구성, 스키마 관리, 테스트 범위만 증가한다.

### 도구별 책임

| 도구 | 책임 |
|---|---|
| DuckDB | 원본 CSV 조회, 프로파일링, 품질 규칙 적용, 상세 데이터 정제 및 집계 |
| Python | DuckDB SQL 실행 자동화, 파라미터 관리, 오류 처리, 행 수와 실행 시간 기록 |
| PostgreSQL | 품질 검사 결과, 파이프라인 실행 이력, 최종 집계 테이블 저장 |
| Superset | PostgreSQL에 저장된 집계 결과 시각화 |

### 제한과 후속 확인

- `read_csv_auto`는 DuckDB 전용 기능이므로 파일 입력 로직과 지표 SQL을
  가능한 한 분리한다.
- DuckDB 사용만으로 모든 SQL이 PostgreSQL과 완전히 호환되는 것은 아니다.
  엔진별 함수와 자료형 차이는 별도로 확인한다.
- DuckDB는 이 프로젝트에서 로컬 배치 처리 엔진이며, 다수 사용자가 동시에
  접속하는 운영 데이터베이스 역할을 맡지 않는다.
- Parquet 변환은 아직 확정된 성능 최적화 결과가 아니다. 동일 쿼리의 CSV와
  Parquet 실행 시간, 파일 크기, 반복 조회 비용을 측정한 뒤 채택 여부를
  결정한다.
- 현재 확인된 793,356건은 품질 규칙을 동시에 적용한 프로파일링 기준값이다.
  재사용 가능한 처리 파이프라인이 이 값을 재현하는지는 구현 단계에서
  별도로 확인해야 한다.
