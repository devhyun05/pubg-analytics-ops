# 데이터 프로파일링

> 문서 상태: 초기 설계
>
> 구현 상태: 미구현
>
> 선행 조건: 원본 파일 다운로드와 입력 승인

## 1. 목적

이 단계는 정제 코드와 품질 규칙을 작성하기 전에 실제 데이터의 구조와 분포를 확인한다.

공개 설명만으로 컬럼명, 타입, 키, 값의 범위를 확정하지 않는다. 실제 파일에서 얻은 프로파일링 결과를 데이터 사전, Python 변환 규칙, 품질 검사, SQL 지표의 공통 근거로 사용한다.

## 2. 입력

이 단계는 [01_DATA_SOURCE_AND_INPUT.md](01_DATA_SOURCE_AND_INPUT.md)의 출력을 입력으로 받는다.

- 입력 승인된 원본 파일 목록
- `source_file_id`
- 데이터셋 버전
- 실제 파일 크기와 체크섬
- 원본 로컬 경로
- 다운로드 및 압축 해제 이력

현재 데이터가 다운로드되지 않았으므로 실제 컬럼과 행 수는 입력으로 확정하지 않는다.

## 3. 처리

### 파일 수준 프로파일링

각 파일에서 다음 항목을 확인한다.

- 파일 경로와 파일명
- 파일 크기
- 형식과 인코딩
- 구분자와 헤더 존재 여부
- 전체 행 수
- 읽기 실패 행 수
- 빈 파일 여부
- 파일 간 헤더 차이

### 컬럼 수준 프로파일링

실제 확인된 각 컬럼에 대해 다음 항목을 계산한다.

- 원본 컬럼명
- 추론 타입
- 타입 변환 성공률
- NULL 건수와 비율
- 빈 문자열 건수
- 고유값 수와 비율
- 최솟값과 최댓값
- 문자열 최소·최대 길이
- 상위 빈도 값
- 값 형식이 다른 사례

고카디널리티 식별자나 플레이어 관련 값은 보고서에 원문 샘플을 노출하지 않는다.

### 관계와 키 후보 조사

다음 내용을 실제 데이터로 확인한다.

- 파일 청크 간 스키마 일치 여부
- `aggregate`와 `deaths` 사이의 공통 키 후보
- 경기 단위 식별자 후보
- 이벤트 단위 중복 판정 키 후보
- 한 경기와 여러 플레이어 또는 이벤트 사이의 관계
- 참조되지 않는 이벤트 또는 경기의 존재 가능성

키는 고유값 수와 중복 분포를 확인한 뒤 후보로 기록한다. 컬럼명만 보고 기본 키로 확정하지 않는다.

### 시간 분석 가능성 조사

다음 조건을 확인한다.

- 날짜 또는 시각 후보 컬럼 존재 여부
- 파싱 가능한 형식과 시간대
- 최소·최대 시각
- 미래 시각 또는 비정상 과거 시각
- 파일 청크별 시간 범위
- 배치 비교 기준으로 사용할 수 있는지 여부

### 품질 규칙 후보 도출

프로파일링 결과를 이용해 다음 품질 규칙의 적용 가능성을 판단한다.

- 필수 컬럼
- 허용 NULL 비율
- 중복 판정 기준
- 참조 무결성
- 숫자 및 시간 범위
- 좌표 범위
- 허용 카테고리
- 파일별 기대 데이터량
- 스키마 변경 감지 기준

프로파일링 자체는 정상·비정상을 최종 판정하지 않는다. 기준선과 품질 규칙 후보를 제공한다.

## 4. 출력

예정 출력은 다음과 같다.

| 출력 | 주요 내용 | 다음 사용 단계 |
|---|---|---|
| 파일 프로파일 | 크기, 행 수, 형식, 읽기 실패 수 | Python 처리 |
| 컬럼 프로파일 | 타입, NULL, 고유값, 범위, 빈도 | Python 처리, 데이터 품질 |
| 관계 프로파일 | 공통 키와 참조 관계 후보 | 데이터 품질, SQL 지표 |
| 시간 프로파일 | 파싱 규칙과 데이터 기간 | 데이터 품질, SQL 지표 |
| 데이터 사전 초안 | 실제 컬럼의 의미와 확인 상태 | 전체 단계 |
| 품질 규칙 후보 | 검사 대상과 기준선 | 데이터 품질 |

출력에는 프로파일링 실행 시각, 대상 파일, 처리 행 수, 소요 시간, 실패 수를 함께 기록한다.

이 출력은 [03_PYTHON_PROCESSING.md](03_PYTHON_PROCESSING.md)의 변환 설계와 [04_DATA_QUALITY.md](04_DATA_QUALITY.md)의 규칙 설계에 전달된다.

## 5. 사용 기술

- Python 3.12
- DuckDB
- CSV 자동 감지와 명시적 스키마 비교
- SQL 집계
- Parquet 또는 구조화된 프로파일 결과
- Markdown 데이터 사전

대규모 CSV를 pandas로 한 번에 메모리에 적재하지 않는다. 전체 집계는 DuckDB의 파일 직접 조회 또는 청크 단위 처리를 사용한다.

## 6. 성공 조건

- 승인된 모든 입력 파일의 읽기 가능 여부가 확인된다.
- 파일별 실제 행 수와 실패 행 수가 기록된다.
- 실제 컬럼명과 타입 후보가 기록된다.
- NULL, 고유값, 최소·최대 범위가 계산된다.
- 청크 간 스키마 차이가 식별된다.
- 데이터 간 공통 키 후보와 근거가 기록된다.
- 시간 분석 가능 여부가 결론으로 남는다.
- 변환 규칙과 품질 규칙을 설계할 수 있는 근거가 생성된다.
- 민감하거나 식별 가능한 원문 값이 공개 프로파일에 노출되지 않는다.

## 7. 실패 가능성

- 자동 타입 추론이 파일마다 다를 수 있다.
- 손상된 행 또는 따옴표 오류로 CSV 파싱이 실패할 수 있다.
- 전체 고유값 계산이 시간과 메모리를 과도하게 사용할 수 있다.
- NULL 표현이 빈 문자열, 문자열 `null`, 특수값 등으로 나뉠 수 있다.
- 파일별 헤더 또는 컬럼 순서가 다를 수 있다.
- 키 후보가 실제로 고유하지 않을 수 있다.
- 시간 컬럼이 여러 형식 또는 시간대를 포함할 수 있다.
- 전체 프로파일링 전에 디스크 또는 실행 시간이 부족할 수 있다.

## 8. 확인 및 복구

- 자동 추론 결과와 명시적 샘플 확인 결과를 비교한다.
- 파싱 실패는 무시하지 않고 파일, 행 위치, 원인을 기록한다.
- 비용이 큰 고유값 계산은 근사치와 정확 계산을 구분해 표시한다.
- 파일별 결과를 저장해 실패 파일만 재실행할 수 있게 한다.
- 프로파일링 실행에도 `run_id`와 `source_file_id`를 부여한다.
- 일부 파일만 처리한 경우 결과를 전체 데이터 결과로 표현하지 않는다.
- 스키마 차이가 발견되면 변환 전에 데이터 사전과 입력 승인 상태를 갱신한다.

## 9. 채용공고 요구사항과의 연결

- 대규모 데이터의 구조와 품질을 조사하는 실무 역량
- 실제 데이터 기반 이벤트 스키마 문서화
- SQL 집계와 필터를 활용한 데이터 탐색
- 데이터 품질 검사 규칙을 근거 있게 설계하는 능력
- 반복 프로파일링 자동화를 위한 Python 활용
- 분석 가능 범위와 데이터 편향을 문서화하는 역량

## 10. 미확정 사항

- 실제 컬럼명과 컬럼 수
- 각 컬럼의 확정 타입
- NULL 표현 방식
- 파일별 실제 행 수
- 고유 키와 복합 키
- `aggregate`와 `deaths`의 조인 조건
- 시간 컬럼과 실제 수집 기간
- 좌표 단위와 유효 범위
- 플레이어 식별 가능 필드 처리 방법
- 전체 프로파일링과 샘플 프로파일링의 실행 범위
- 프로파일 결과 저장 형식과 경로
