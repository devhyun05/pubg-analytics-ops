# 프로젝트 복습 노트

이 문서는 프로젝트를 직접 설명할 수 있도록, 구현 과정을 이해한 내용과
면접에서 주의해야 할 표현을 단계별로 기록한다.

## 1. 분석 데이터 선정과 공간 집계

### 내가 이해한 내용

약 6,500만 건의 사망 이벤트 중 추락(`Falling`)과 익사(`Drown`)에 해당하는
980,079건을 환경 사망 후보로 추출했다. 이후 `(0,0)` 좌표 약 18만 건,
맵 정보가 없는 행, 중복 행, 좌표 범위를 벗어난 행, 날짜와 연결할 수 없는
행 등을 제외해 최종 793,356건을 분석에 사용했다.

맵을 먼저 250m 정사각형 격자로 나누어 환경 사망 집중 지역을 탐색하고,
다시 100m 격자로 세분화했다. 이후 에란겔·미라마와 추락·익사 조합별로
사망 건수가 많은 격자에 1위, 2위, 3위 등의 순위를 부여했다.

### 기억해야 할 점

- 환경 사망은 현재 분석에서 `Falling`과 `Drown`으로 정의했다.
- `(0,0)` 좌표는 오류라고 확정한 것이 아니라 위치 분석에 사용할 수 없어 제외했다.
- 순위는 전체 통합 순위가 아니라 맵과 사망 원인 조합별 순위다.
- 사망 건수뿐 아니라 서로 다른 경기 수와 발생 날짜 수도 함께 확인했다.
- 방문자 수가 없으므로 집중 격자를 가장 위험한 장소라고 단정하지 않는다.
- 최종 결과는 반복적인 환경 사망이 관측된 QA 점검 후보 위치다.

## 이후 복습할 내용

- 250m 격자와 100m 격자의 역할
- 공간 집중 지표와 순위 계산 방법
- 분석 결과 해석과 한계
- PostgreSQL 저장과 파이프라인 실행 이력
- Superset 대시보드와 히트맵
- QA 전달 내용과 후속 조치
