# 데이터 출처 및 입력

> 문서 상태: 초기 설계
>
> 구현 상태: 데이터 미다운로드
>
> 공개 메타데이터 확인일: 2026-07-30

## 1. 목적

이 단계는 원본 데이터의 출처, 공개 범위, 파일 구성, 로컬 보관 원칙을 확인하고 프로파일링 가능한 입력인지 판단한다.

데이터를 다운로드할 수 있다는 사실만으로 사용 권리가 모두 확인된 것은 아니므로, Kaggle 표시 라이선스와 원천 서비스의 권리 위험을 분리해 기록한다. 또한 공개된 전체 규모와 프로젝트에서 실제로 처리한 범위를 구분할 기준을 만든다.

## 2. 입력

이 단계의 입력은 다음과 같다.

- [전체 흐름 문서](00_END_TO_END_FLOW.md)
- Kaggle 데이터셋 페이지
- Kaggle 공개 데이터셋 메타데이터
- Kaggle 공개 파일 목록
- Creative Commons CC0 안내
- OP.GG의 현재 이용약관

대상 데이터셋은 다음과 같다.

| 항목 | 확인 내용 | 상태 |

| 제공자 표시명 | KP | 확인 |
| Kaggle 계정 | `skihikingkevin` | 확인 |
| 데이터셋 식별자 | `skihikingkevin/pubg-match-deaths` | 확인 |
| Kaggle 공개 상태 | 공개, Version 3, Ready | 확인 |

확인 URL은 다음과 같다.

## 3. 처리

### 출처와 권리 확인

Kaggle에는 CC0로 표시되어 있다. CC0는 일반적으로 복제, 변형, 배포를 허용하고 출처 표시를 의무화하지 않는다.

다만 업로더는 제3자 서비스인 `pubg.op.gg`에서 데이터를 추출했다고 설명한다. 현재 OP.GG 약관은 스크래핑과 허가 없는 콘텐츠 복제·배포를 금지하지만, 이 약관이 2018년 수집 당시에도 동일했는지는 확인되지 않았다. 따라서 개인 포트폴리오 분석은 진행 가능한 것으로 판단하되, 원본 데이터 재배포 권리는 완전히 확인된 것으로 표현하지 않는다.

프로젝트는 다음 원칙을 적용한다.

- 원본 데이터는 로컬 분석 목적으로만 사용한다.
- GitHub에는 원본 또는 원본을 복원할 수 있는 대용량 상세 데이터를 올리지 않는다.
- 공개 산출물은 집계 결과, 품질 결과, 코드, 문서, 대시보드로 제한한다.
- 실제 파일에서 플레이어 식별 가능 정보가 확인되면 공개 산출물에서 제거하거나 가명 처리한다.
- KRAFTON, PUBG 또는 OP.GG가 프로젝트를 후원하거나 검증했다고 표현하지 않는다.

### 공개 파일 구성

| 경로 또는 패턴 | 개수 | 역할 | 크기 합계 |
|---|---:|---|---:|
| `aggregate/agg_match_stats_0.csv`부터 `aggregate/agg_match_stats_4.csv` | 5 | 경기 메타데이터와 플레이어 집계 통계 | 약 10.53 GB |
| `deaths/kill_match_stats_final_0.csv`부터 `deaths/kill_match_stats_final_4.csv` | 5 | 사망 이벤트 | 약 9.75 GB |
| `erangel.jpg`, `miramar.jpg` | 2 | 지도 이미지 | 약 2.81 MB |

데이터셋 설명은 `aggregate`와 `deaths` 두 ZIP을 언급하지만, 현재 API는 디렉터리 아래 CSV 파일을 논리 파일로 표시한다. 실제 다운로드 압축 구조는 다운로드 후 확인한다.

### 다운로드 방식

브라우저에서는 Kaggle 로그인 후 데이터셋 페이지의 `Download` 기능을 사용한다.

CLI를 사용할 경우 예정 명령은 다음과 같다.

```bash
kaggle auth login
kaggle datasets files skihikingkevin/pubg-match-deaths
kaggle datasets download \
  -d skihikingkevin/pubg-match-deaths \
  -p data/raw
```

이 명령은 현재 실행하지 않았다. 토큰 값은 저장소, 문서, 로그에 기록하지 않는다.

### 로컬 저장 정책

예정 저장 위치는 다음과 같다.

```text
data/
├── raw/          # 다운로드 원본, 읽기 전용 취급
├── staged/       # 압축 해제 또는 처리 준비 파일
├── curated/      # 정제된 Parquet
└── quarantine/   # 처리 실패 또는 품질 문제 파일
```

디렉터리와 설정은 구현 단계에서 생성한다. 원본 파일은 수정하지 않고, 변환 결과를 별도 위치에 기록한다.

다운로드 전에 최소 30 GB의 빈 공간을 확인한다. 전체 파이프라인과 Parquet, Docker 볼륨, 임시 파일을 함께 운영하려면 50 GB 이상, 안정적인 작업을 위해 70 GB 이상을 권장한다.

### 입력 승인 조건

원본 파일이 다음 단계로 넘어가려면 아래 항목을 기록해야 한다.

- 데이터셋 식별자와 버전
- 다운로드 시각
- 실제 다운로드 파일명
- 파일별 바이트 크기
- 가능하면 파일 체크섬
- 압축 해제 성공 여부
- 로컬 저장 경로
- 다운로드 및 압축 해제 과정의 오류
- 원본 파일이 Git 추적 대상이 아님을 확인한 결과

## 4. 출력

이 단계의 출력은 입력 데이터 명세와 원본 파일 인벤토리다.

예정 출력 항목은 다음과 같다.

| 필드 | 설명 |
|---|---|
| `dataset_ref` | Kaggle 데이터셋 식별자 |
| `dataset_version` | 다운로드한 버전 |
| `source_file_id` | 파일 식별자 |
| `source_path` | 로컬 원본 경로 |
| `size_bytes` | 실제 파일 크기 |
| `checksum` | 파일 무결성 확인값 |
| `downloaded_at` | 다운로드 시각 |
| `ingestion_status` | 프로파일링 입력 승인 상태 |

승인된 원본 파일과 입력 명세는 [02_DATA_PROFILING.md](02_DATA_PROFILING.md)의 입력이 된다.

## 5. 사용 기술

- Kaggle 웹 인터페이스 또는 Kaggle CLI
- 로컬 파일 시스템
- 체크섬 도구
- Git 제외 규칙
- Markdown 기반 출처 기록

이 단계에서는 Python 처리 코드, DuckDB 쿼리, 데이터베이스 적재를 실행하지 않는다.

## 6. 성공 조건

- 데이터셋 페이지와 공개 파일 목록에 접근할 수 있다.
- 출처, 제공자 표시명, 데이터셋 식별자, 버전, 표시 라이선스가 기록된다.
- 다운로드된 경우 실제 파일 수와 파일 크기가 기록된다.
- 원본과 변환 결과의 저장 위치가 분리된다.
- 원본 파일이 GitHub에 포함되지 않는다.
- 다운로드한 범위와 공개된 전체 규모가 구분된다.
- 프로파일링에 전달할 파일 목록이 고정된다.

## 7. 실패 가능성

- Kaggle 로그인 또는 인증이 실패할 수 있다.
- 데이터셋이 비공개 또는 삭제 상태로 변경될 수 있다.
- 공개 메타데이터와 실제 압축 파일 구성이 다를 수 있다.
- 다운로드 중 파일이 일부만 저장될 수 있다.
- 압축 해제 중 디스크 공간이 부족할 수 있다.
- 동일 이름의 파일을 잘못 덮어쓸 수 있다.
- 원본 데이터가 실수로 Git 추적 대상에 포함될 수 있다.
- 원천 서비스의 과거 이용약관을 확인하지 못할 수 있다.

## 8. 확인 및 복구

- 인증 실패 시 토큰 값을 출력하지 않고 Kaggle 로그인 상태와 CLI 인증 설정만 확인한다.
- 다운로드 실패 시 불완전 파일을 승인하지 않고 크기와 체크섬을 다시 확인한다.
- 디스크 부족 시 전체 다운로드를 중단하고 처리 범위를 재결정한다.
- 메타데이터와 파일 구성이 다르면 실제 파일을 기준으로 인벤토리를 갱신한다.
- 원본 파일이 Git 추적 대상에 들어간 경우 commit 전에 추적을 중단하고 비밀값 포함 여부를 점검한다.
- 권리 범위가 불명확하면 원본 재배포를 하지 않고 분석 결과만 공개한다.

## 9. 채용공고 요구사항과의 연결

- 데이터 출처와 사용 범위를 검토하는 데이터 운영 역량
- 대규모 입력 데이터 인벤토리 관리
- 개인정보와 인증 토큰을 다루는 보안 의식
- 전체 데이터 규모와 실제 처리 범위를 구분하는 정확한 문서화
- 반복 가능한 다운로드 절차와 입력 승인 기준 수립
- Git 기반 프로젝트에서 원본 데이터를 분리하는 운영 원칙

## 10. 미확정 사항

- 실제 다운로드 압축 파일 크기
- 압축 파일 내부의 현재 디렉터리 구조
- 실제 파일별 행 수
- 정확한 전체 경기 수와 이벤트 수
- 데이터 수집 시작일과 종료일
- 실제 컬럼명과 타입
- 플레이어 식별 가능 필드 존재 여부
- 파일별 체크섬
- 2018년 당시 OP.GG 이용약관
- 프로젝트에서 처리할 전체 또는 부분 파일 범위
